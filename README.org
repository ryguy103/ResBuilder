* Overview

A plain-text, git-versioned system for managing resumes and job applications.

Philosophy: /Plain text, version controlled, future-proof./

* Quick Start

** Prerequisites

- =make= (standard on macOS/Linux)
- LaTeX is *optional* — only needed for PDF generation

** Markdown Workflow (No LaTeX Required)

#+begin_src shell
make help       # Show all available commands
make view       # Display plain text resume in terminal
make copy       # Copy plain text resume to clipboard
make save       # Save dated copies to output/ folder
make md         # Open resume.md in your editor
make clean      # Remove generated files
#+end_src

This is the recommended workflow for most job applications. ATS systems prefer plain text anyway.

** PDF Workflow (Optional - Requires LaTeX)

If you want nicely formatted PDFs, install LaTeX first:

On macOS:
#+begin_src shell
brew install --cask mactex-no-gui
#+end_src

Then:
#+begin_src shell
make pdf        # Build resume PDF
make cover      # Build cover letter PDF
make all        # Build both PDFs
make website    # Build public resume (no phone/address)
#+end_src

Output files are named =YYYYMMDD--ryan-laxson-resume.pdf= and placed in =output/=.

* Public vs Private Resume

The resume supports two versions:

- *Private* (=make resume=): Full contact info including phone and city/state. Use for job applications.
- *Public* (=make website=): Omits phone and shows only "United States". Use for public website.

Both versions are built from the same =resume.tex= source. The =resume-public.tex= wrapper sets a flag that triggers the conditional:

#+begin_src latex
\ifdefined\publicversion
  \address{United States}{}{}      % PUBLIC
\else
  \address{City, State}{}{}        % PRIVATE
  \phone[mobile]{(555) 123-4567}
\fi
#+end_src

* Workflow

** Master Resume (main branch)

The =main= branch contains your canonical, comprehensive resume with /all/
experience, skills, and achievements. This is your source of truth.

** Job-Specific Applications (feature branches)

For each job application:

1. Create a branch:
   #+begin_src shell
   git checkout -b apply/company-name-2026-01
   #+end_src

2. Tailor =resume.tex= for the specific role:
   - Choose the appropriate summary variant (Support Ops, Tooling, Customer Experience)
   - Reorder bullet points to highlight JD requirements
   - Use keywords from the job description where genuine
   - Comment out irrelevant items to fit on one page

3. Customize =cover-letter.tex= for the position:
   - Follow the methodology in the template comments
   - Map accomplishments to their stated needs
   - Include at least one metric

4. Generate PDFs:
   #+begin_src shell
   make all
   #+end_src

5. Commit your tailored versions:
   #+begin_src shell
   git add -A
   git commit -m "Tailored resume for Company Name - Position Title"
   #+end_src

** Summary Variants

Three summary options are included in =resume.tex=. Uncomment the one that best matches each role:

1. *Support Operations / AI Automation* (default)
2. *Tooling / Engineering Focus*
3. *Customer Experience Focus*

** moderncv Styles

In =resume.tex=, change the style:
#+begin_src latex
\moderncvstyle{classic}       % casual, classic, banking, oldstyle, fancy, contemporary
\moderncvstyle{contemporary}  % modern style with optional QR code (use 'noqr' to disable)
#+end_src

** Color Themes

#+end_src

* Cover Letter Methodology

The cover letter template includes guidance based on effective tailoring:

1. *Opening (2-3 sentences)*: Role, genuine interest, hint at fit
2. *Body 1 - Why You're a Fit*: 2-3 accomplishments mapped to JD needs
   - Use their language
   - Include at least one metric
3. *Body 2 - Why This Company*: Specific reason (not generic)
4. *Closing*: Brief call to action, thank them

Keep under 400 words. The template includes a strength mapping reference to help select the right accomplishments for each JD.

* Tips

- Keep master resume comprehensive; trim on branches
- Use =git diff= to compare versions
- Comment out sections with =%= instead of deleting
- One page is ideal for most applications
- Don't over-optimize: well-matched 80% beats keyword-stuffed 100%
- Test both =make resume= and =make website= after editing contact info

* Pre-Submission Checklist

** Resume
- [ ] Summary adapted to role's domain
- [ ] Top 3 bullets address top 3 JD requirements
- [ ] All relevant JD keywords present (where genuine)
- [ ] Metrics preserved: $250K, 90→3 min
- [ ] No passive language ("exposure to," "familiar with")

** Cover Letter
- [ ] Company name correct throughout
- [ ] Role title matches exactly
- [ ] At least one specific company reference (not generic)
- [ ] At least one metric included
- [ ] Under 400 words

** Authenticity
- [ ] Every claim defensible in an interview
- [ ] Nothing inflated or fabricated
- [ ] Reads naturally (direct, practical tone)

#+begin_src org
| Company | Role | Branch               | Applied    | Status       | Follow-up  | Notes |

Standard lifecycle statuses:
- =Draft= - Working on tailored resume
- =Applied= - Submitted application
- =No Response= - No reply after 2+ weeks
- =Phone Screen= - Initial recruiter call
- =Technical= - Technical interview stage
- =Onsite= - Final round interviews
- =Offer= - Received offer
- =Accepted= / =Declined= - Final outcome
- =Rejected= - They said no

#+end_src
